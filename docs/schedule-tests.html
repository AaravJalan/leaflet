src/lib/schedule.test.ts

What the schedule tests check

This file tests src/lib/schedule.ts, the code that turns the date and time fields on the announcement form into stored timestamps and turns those timestamps back into text like “Week of Nov 9, Mon, Fri, 6:00 PM to 7:30 PM”.

  • 77 tests passing
  • 10 test groups
  • 8 functions covered
  • CI runs it in 3 time zones

Why it matters

Every announcement with a time goes through these functions, both when it is saved and when it is shown.

CreateAnnouncement.tsxbuildWhen saves a new event time
EditAnnouncement.tsxbuildWhen plus the to…Input helpers to refill the form
AnnouncementCard.tsx, AnnouncementDetail.tsxformatWhen shows the time to readers
ScheduleFields.tsxWEEKDAYS draws the day picker

The fixed test week

Most tests use the same week, Monday Nov 9 to Sunday Nov 15, 2026. Weeks start on Monday, so Sunday is the last day of the week, not the first. Many tests exist to pin down that one rule.

Mon9Tue10Wed11Thu12Fri13Sat14Sun15

JavaScript numbers Sunday as 0, but the app puts it last.

13tests

mondayOf

Finds the Monday of the week that contains a given date.

  • Every day from Mon to Sun maps back to Nov 9. Sunday goes back six days, not forward one.
  • Works across a month change, a year change and a leap day.
  • Returns local midnight.
  • A loop over every day from 2024 to 2027 checks that the result is always a Monday, 0 to 6 days earlier, and unchanged if you run it again. This covers every daylight saving change in those years.
mondayOf('2026-01-01') → 2025-12-29 mondayOf('2024-02-29') → 2024-02-26
17tests

dateInWeek

Takes a week, a weekday and a time like “18:30” and returns that exact moment.

  • Each weekday lands on the right date, and Sunday comes after Saturday.
  • Any date inside the week gives the same answer.
  • Sets hours and minutes and clears seconds, including 00:00 and 23:59.
  • Rolls into the next month, the next year, and over Feb 29.
  • Keeps 10:15 as 10:15 on the Sundays when US clocks spring forward or fall back.
  • A blank or garbled time falls back to midnight, and “7” means 7:00.
11tests

toDateInput · toTimeInput · toDateTimeInput

Turn a stored timestamp back into the text format HTML date and time inputs expect, so the edit form can be refilled.

  • Formats use leading zeros (2026-01-05, 09:05, 2026-01-05T09:05).
  • Midnight and 23:59 stay on the correct local day.
  • null and 0 both count as empty and return ''.
5tests

buildWhen one-time events

Turns the form's start and end fields into what gets saved.

  • Turns both datetime fields into timestamps. Start and end can each be left blank.
  • Ignores weekly fields still filled in after the user switches back to “once”.
  • Saving and then loading the edit form gives back the exact text that was typed.
13tests

buildWhen weekly events

Turns the week, days and times into what gets saved.

  • Throws “Pick a week, at least one day, and a start time.” if the week, start time or days are missing.
  • Saves the Monday of the chosen week, even if the user picked a Thursday.
  • Uses the earliest selected day, Mon to Sun, as the start date, no matter what order the days were clicked in. If only Sunday is picked, it starts on the 15th, not the 9th.
  • Keeps the selected days in the order given and does not change the input array.
  • Ignores one-time fields left over from before.
  • Loading the edit form or formatting the saved event gives back what the user picked.
days [FRI, TUE, THU] at 09:00 → startsAt Tue Nov 10, 9:00 AM
7tests

formatWhen one-time events

The text shown on announcement cards and the detail page.

  • Shows the start alone, or a full start-to-end range.
  • Ranges that end the next day or the next month show the correct end date.
  • Midnight shows as 12:00 AM and noon as 12:00 PM.
  • Shows nothing if there is no start, even when there is an end.
Sat, Oct 31, 10:00 PM to Sun, Nov 1, 1:00 AM
10tests

formatWhen weekly events

The same text for repeating events.

  • Shows the week, the days and the time range, and leaves out the end when there isn't one.
  • Sorts days Mon to Sun without changing the saved array.
  • Shows “Weekly” if no week is set. Leaves out the time if there is no start.
  • Skips unknown day numbers.
  • Uses the one-time format when there are no repeat days, including older saved records that have no repeatDays field.
Week of Nov 9, Mon, Wed, Fri, Sun, 6:00 PM

What the suite guards against

Time zone and DST drift

Everything runs in local time. CI runs the suite in UTC, America/Chicago and Pacific/Auckland so off-by-one-day bugs show up.

Sunday placement

Sunday is 0 in JavaScript but the last day of the week in the app. The tests check this in every function that deals with weekdays.

Round trips

Saving an event and opening the edit form must give back the same values the user typed.

Messy input

Leftover fields from the other schedule mode, blank or garbled times, and old records missing fields.
